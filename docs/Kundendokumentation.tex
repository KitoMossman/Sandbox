	\section{Einstieg über den Infrastructure Hub}
	Der zentrale Einstiegspunkt für alle Entwicklungsarbeiten ist der \textbf{Infrastructure Hub} unter:
	\begin{center}
		\url{https://sandbox.ma.ki/}
	\end{center}
	
	Dieses Dashboard aggregiert alle relevanten Dienste. Von hier aus haben Sie direkten Zugriff auf die Verwaltungsoberflächen und Terminals, ohne manuell SSH-Verbindungen konfigurieren zu müssen.
	
	\section{Szenario A: Deployment einer PHP-Anwendung mit SQL-Datenbank}
	Dieses Verfahren nutzt das integrierte \textbf{CloudPanel} zur Bereitstellung klassischer Web-Stacks.
	
	\subsection{Schritt 1: Website-Container erstellen}
	\begin{enumerate}
		\item Öffnen Sie die \textbf{CloudPanel UI} über den Link im Hub.
		\item Wählen Sie im Menü \textbf{Sites} $\rightarrow$ \textbf{Add Site} $\rightarrow$ \textbf{Create a PHP Site}.
		\item Geben Sie die gewünschte Domain (z.\,B. \texttt{projekt.sandbox.ma.ki}) und die benötigte PHP-Version an.
	\end{enumerate}
	
	\subsection{Schritt 2: Datenbank anlegen}
	\begin{enumerate}
		\item Navigieren Sie innerhalb der Site-Verwaltung zu \textbf{Databases}.
		\item Erstellen Sie eine neue Datenbank. Notieren Sie sich den Datenbanknamen, den User und das generierte Passwort für Ihre \texttt{.env}- oder Konfigurationsdatei.
	\end{enumerate}
	
	\subsection{Schritt 3: Deployment der Dateien}
	Sie können Ihre Dateien entweder über den integrierten \textbf{File Manager} hochladen oder den im Hub verlinkten \textbf{Host-Terminal} nutzen. Das Zielverzeichnis lautet:
	\texttt{/htdocs/[ihre-domain]/}

	\section{Szenario B: Deployment einer Docker-App via Compose YAML}
	Für containerisierte Microservices nutzen Sie die \textbf{Portainer UI}, die innerhalb der isolierten Sandbox-Umgebung operiert.
	
	\subsection{Schritt 1: Stack-Definition}
	\begin{enumerate}
		\item Öffnen Sie \textbf{Portainer} über den Infrastructure Hub.
		\item Wählen Sie unter \textbf{Stacks} die Option \textbf{+ Add stack}.
		\item Geben Sie Ihre Docker-Compose-Konfiguration im Web-Editor ein.
	\end{enumerate}
	
	\begin{lstlisting}[language=bash, caption=Beispiel einer docker-compose.yaml]
		services:
		web-app:
		image: nginx:latest
		ports:
		- "8080:80"
		restart: always
	\end{lstlisting}
	
	\subsection{Schritt 2: Deployment und Zugriff}
	Klicken Sie auf \textbf{Deploy the stack}. Ihre Anwendung ist anschließend über die IP der Docker-Sandbox (\texttt{192.168.100.22}) und den von Ihnen definierten Port erreichbar.
	
	\section{Fehlerbehebung und Selbstheilung}
	Die Infrastruktur ist nach dem \textbf{Trampolin-Prinzip} aufgebaut, um Ausfälle durch Fehlkonfigurationen zu minimieren:
	
	\begin{itemize}
		\item \textbf{Automatisierte Isolation:} Erkennt das System einen Syntaxfehler in einer vHost-Konfiguration (z.\,B. durch fehlerhaftes Copy-Paste), wird dieser Dienst isoliert (\texttt{.broken}), während alle anderen Projekte online bleiben.
		\item \textbf{LXC-Container-Reset:} Im Infrastructure Hub steht unter dem Reiter „Recovery“ eine Schnell-Wiederherstellung zur Verfügung. Diese nutzt den hinterlegten Snapshot \texttt{clean-state}, um nur die Docker-Umgebung zurückzusetzen, ohne den Host neu zu starten.
		\item \textbf{Factory-Reset:} Sollte die Umgebung instabil werden, kann man im Infrastructure Hub über den Reiter "`Recovery"` einen automatisierten Werksreset auslösen. Innerhalb weniger Minuten wird der exakte Auslieferungszustand ("`Clean-State"') wiederhergestellt.
	\end{itemize}
